# Requirements: MVP, the clinic catalog

## Context

Phases 1 and 2 on `specs/roadmap.md` are done: a Hono app with a responsive layout, a dev server, tests, lint, and formatting (see `specs/2026-10-20-hello-hono/` and `specs/2026-10-20-dev-and-lint/`).

The MVP is the **clinic catalog, roadmap Phases 6–29**: a SQLite database with seed data, and linked pages for agents, their ailments, and the therapies that treat them. It's the first version of AgentClinic with real content, which is what a course student or a booth demo needs to show the app doing something.

It follows `specs/mission.md` ("Small steps", "Delight matters", "Every screen") and `specs/tech-stack.md` (Hono JSX, Prisma with SQLite, Vitest, responsive design).

## Scope

In scope (roadmap phases):

- **Database (6–8):** Prisma with SQLite, a shared client module, and `npm run seed`.
- **Agents (9–14):** `Agent` model, seeded agents, list and detail pages, a friendly 404, and an "Agents" nav link.
- **Ailments (15–22):** `Ailment` model, seeded ailments, list and detail pages, and the agents ↔ ailments link shown on both detail pages.
- **Therapies (23–29):** `Therapy` model, seeded therapies, list and detail pages, the therapies ↔ ailments link, and suggested therapies on each agent's page.

Out of scope (after the MVP):

- Appointments and booking (30–36) and dashboards (37–41)
- Tailwind and CI (3–5); the hand-written `static/styles.css` keeps going
- Landing page, design pass, and Playwright (42–49)
- Creating, editing, or deleting agents, ailments, or therapies through the UI (data comes from the seed)
- Authentication

## Decisions

### Database

| Decision | Choice | Why |
|---|---|---|
| ORM version | Prisma **7.10** (`prisma`, `@prisma/client`), the latest stable | npm's `latest` tag points at `8.0.0-rc.23`, a release candidate; "Boring and reliable" means stable |
| SQLite driver | `@prisma/adapter-better-sqlite3` + `better-sqlite3` | Prisma 7 talks to SQLite through a driver adapter |
| Install scripts | Approve `better-sqlite3`'s (and Prisma's, if asked) install scripts with `npm install-scripts approve` | npm 11 blocks install scripts by default here, and `better-sqlite3` needs its native binary |
| Config | `prisma.config.ts` (schema path, migrations path, seed command, datasource URL) | Prisma 7's configuration file |
| Generated client | `generator client { provider = "prisma-client"; output = "../src/generated/prisma" }`, git-ignored | Typed client inside `src/`, regenerated by `npm run db:generate` |
| Database file | `DATABASE_URL`, defaulting to `file:./prisma/dev.db`; `*.db` files are git-ignored | No `.env` file or dotenv dependency needed to get started |
| Shared client | `src/db.ts` exports one `PrismaClient` | Phase 7; every route uses the same client |
| Migrations | `npm run db:migrate` (`prisma migrate dev`); migrations committed under `prisma/migrations/` | Students can see each schema change |
| Seed | `prisma/seed.ts`, run with `npm run seed`; clears the tables, then creates everything, so it can be re-run safely | One command gives every student and demo the same data |
| Setup | `npm run setup` = migrate + seed | One command after `npm install` |

### Models

All ids are autoincrement integers; pages use a unique, URL-friendly `slug`.

| Model | Fields | Relations |
|---|---|---|
| `Agent` | `id`, `slug`, `name`, `role` (e.g. "Coding assistant"), `bio` | many-to-many with `Ailment` |
| `Ailment` | `id`, `slug`, `name`, `description` | many-to-many with `Agent` and with `Therapy` |
| `Therapy` | `id`, `slug`, `name`, `description`, `durationMinutes` | many-to-many with `Ailment` |

Relations use Prisma's implicit many-to-many tables.

### Seed data

- About 6 agents, 6 ailments, and 5 therapies, written in the clinic's warm, playful voice (e.g. ailments "Context-window exhaustion", "Hallucination anxiety", "Prompt fatigue"; therapies "Context decluttering", "Grounding exercises").
- Every agent has at least one ailment, every ailment is treated by at least one therapy, and at least one ailment affects several agents, so every page has something to show.

### Pages and routes

| Route | Page |
|---|---|
| `GET /agents` | All agents, by name: name, role, and their ailments |
| `GET /agents/:slug` | Agent's bio, ailments (linked), and suggested therapies (linked) |
| `GET /ailments` | All ailments, by name, with how many agents have each |
| `GET /ailments/:slug` | Description, affected agents (linked), and therapies that treat it (linked) |
| `GET /therapies` | All therapies, by name, with duration |
| `GET /therapies/:slug` | Description, duration, and ailments it treats (linked) |

- Each feature is its own Hono sub-app (`src/routes/agents.tsx`, `ailments.tsx`, `therapies.tsx`), mounted with `app.route()`, per the tech stack.
- Each page sets its own `<title>` (e.g. "Agents · AgentClinic").
- **Suggested therapies** for an agent: every therapy that treats at least one of the agent's ailments, listed once, ordered by how many of the agent's ailments it treats, then by name.
- **Not found:** an unknown slug on any detail page returns `404` with a friendly page in the layout ("We couldn't find that agent…") and a link back to the list. Phase 13 asks for agents; the MVP uses the same page for ailments and therapies.
- **Navigation:** the header gets "Agents", "Ailments", and "Therapies" links as each section lands (Phase 14 plus its equivalents).
- **Empty lists** show a friendly message instead of a blank page.

### Responsive design

Per "Responsive design" in the tech stack:

- List pages are a grid of cards: 1 column on phones, 2 from `40rem`, 3 from `64rem`.
- Header navigation wraps on narrow screens, and every nav link and card link has a 44px tap target.
- No horizontal scrolling from 320px up.

### Testing

| Decision | Choice | Why |
|---|---|---|
| Test database | Tests use a separate SQLite file (`prisma/test.db`). A Vitest global setup applies migrations and seeds it once per run | Tests run against real data and never touch `dev.db` |
| Route tests | `app.request()` for every page: status, title, key content, links between pages, ordering, and the 404s | Per "Testing and validation" in the tech stack |
| Logic tests | Suggested-therapy ranking tested directly | It's the one non-trivial query |
